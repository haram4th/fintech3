1. 서비스 개요

1-1. 서비스 한 줄 정의

여러 핀테크 앱(토스, 카카오페이, 네이버페이 등)에 분산된 자산과 금융 정보를 하나의 통합 대시보드와 신뢰 기반 라이브 금융 콘텐츠로 연결해 주는 모바일 핀테크 서비스입니다.

1-2. 배경

  • 사용자는 여러 개의 핀테크 앱을 병행 사용하며, 각 서비스의 장단점을 비교·선택함.
  • SNS 인플루언서와 지인 추천, 라이브 방송 등을 통해 금융 정보를 소비하는 패턴 증가.
  • 자산이 여러 플랫폼에 분산되어 있어, 전체 자산을 한 번에 파악하기 어려움.

1-3. 목표

  • 초보자도 이해하기 쉬운 시각적 금융 콘텐츠 제공.
  • 모든 자산을 한 화면에서 확인 가능한 통합 자산 대시보드 제공.
  • 전문가/셀러와의 신뢰 기반 라이브 소통 경험 제공.
  • 커뮤니티를 통한 소속감 형성과 반복 방문 유도.

2. 페르소나 정의 – 박지현

2-1. 기본 정보

  • 이름: 박지현
  • 직업: 마케팅 에이전시 AE
  • 거주: 서울 성수동
  • 특징: 디지털 환경에 매우 친숙, SNS 기반 소비 패턴, 트렌드에 민감

2-2. 현재 이용 행태

  • 토스, 카카오페이, 네이버페이 등 복수의 핀테크 앱 동시 사용.
  • 라이브 방송 기반 금융 콘텐츠에 관심 증가.
  • 주식, 예금, 펀드 등 자산이 다방면에 분산.

2-3. Needs

  • 친숙한 언어와 시각적 표현(영상, 인포그래픽)으로 제공되는 금융 정보.
  • 라이브 방송 중 실시간 질문/응답이 가능한 환경.
  • 단골 셀러/전문가 중심의 신뢰도 높은 추천 콘텐츠.
  • 전체 자산을 한눈에 파악하고 리스크를 최소화할 수 있는 구성.

2-4. Pain Points

  • 어려운 금융 용어, 어디서부터 시작해야 할지 막막함.
  • 자산이 여러 곳에 흩어져 있어 한 번에 파악 불가.
  • 과장된 후기/광고성 리뷰에 대한 피로감.

3. 문제 정의 & 기획 방향

3-1. 문제 정의

  • 복잡한 용어와 UI로 인해 금융 초보자의 진입 장벽이 높음.
  • 후기·리뷰 중심 정보는 광고성이 강해 신뢰도 낮음.
  • 자산이 여러 플랫폼에 분산되어 종합적인 자산 파악이 어려움.
  • DM·비공식 채널을 통한 정보 공유는 실수와 혼선을 유발.

3-2. 기획 방향

  • 신뢰/이해/재미 중심 설계 – 쉬운 언어 + 시각화 + 직관적 흐름.
  • 실시간·몰입형 콘텐츠 – 라이브 방송, 채팅, Q&A.
  • 커뮤니티 기반 유지 – 같은 관심사 유저 간 소통 장려.
  • 데이터 기반 추천 – 사용자 특성·행동 기반 전문가/상품 추천.

4. 핵심 가치 제안 (Value Proposition)

Easy – 쉽게 이해하는 금융

금융 용어를 풀어 쓴 카드형 설명과 짧은 영상/인포그래픽으로 “보면서 이해하는” 경험 제공.

Trust – 신뢰 기반 추천

팔로우한 전문가·셀러의 라이브와 콘텐츠를 중심으로 상품을 탐색하고, 실시간 Q&A로 신뢰를 강화.

View All – 자산 통합 한눈에

여러 앱에 흩어진 계좌·포인트·투자 자산을 한 화면 대시보드로 통합 시각화하여 리스크와 총액을 바로 확인.

5. 주요 기능 정의

5-1. 기능 목록

기능 ID 기능명 설명 우선순위
F-001 자산 통합 대시보드 외부 금융사 API 연동을 통해 계좌/투자/포인트를 한 화면에 시각화. 상
F-002 맞춤 영상/라이브 추천 관심 카테고리와 자산 상황에 맞춘 금융 영상·라이브 방송 추천. 상
F-003 전문가 팔로우 & 피드 신뢰하는 전문가/셀러를 팔로우하고, 해당 전문가 중심 피드 제공. 중
F-004 라이브 채팅 & Q&A 라이브 방송 시 실시간 채팅, 질문 고정, 답변 하이라이트 기능 제공. 상
F-005 커뮤니티 채널 관심사 기반 소규모 채널에서 방송 후기, 질문, 정보 공유. 중
F-006 피드백 & 개선 로그 사용자 오류 신고 및 의견 수집, 빠른 개선 사항 공지. 하

5-2. 주요 API 설계 예시

  • GET /assets/summary – 사용자 전체 자산 요약 조회
  • GET /videos/recommend – 맞춤 금융 영상/라이브 추천 리스트
  • POST /experts/follow – 전문가 팔로우/언팔로우
  • POST /feedback – 앱/콘텐츠 관련 피드백 등록

6. 요구사항 정의서 요약

6-1. 우리가 이 일을 해야 하는 이유

  • 분산된 자산 정보로 인해 사용자 불안과 피로도가 증가.
  • 신뢰할 만한 금융 정보 채널에 대한 수요가 높음.
  • 라이브·커뮤니티 기반 금융 소비 트렌드가 확대되는 시점.

6-2. 접근 방향성

  • 유저 스토리 기반 기능 정의 (박지현의 실제 행동 기준).
  • “기능”이 아닌 “가치”를 중심으로 설명되는 화면/플로우 설계.
  • 빠른 실행과 반복(실험 → 피드백 → 개선)을 전제로 한 MVP 구축.

6-3. 대표 유저 스토리 (User Story)

  • “자산이 여기저기 흩어져 있어서, 한 화면에서 전체 자산을 확인하고 싶다.”
  • “복잡한 글보다 영상을 통해 쉽게 금융 콘텐츠를 소비하고 싶다.”
  • “내가 믿는 전문가가 추천하는 상품만 보고 싶다.”
  • “방송을 보면서 바로 질문하고, 실시간으로 답변을 받고 싶다.”

7. 고객 여정맵 요약

7-1. 단계별 요약

단계 행동 인식/감정 Pain Point 기회요소
1) 인지 SNS, 인플루언서, 지인 추천으로 서비스 노출 “새로운 금융 앱인가?” 호기심 광고성 메시지에 대한 피로 신뢰도 높은 콘텐츠/셀러 강조 메시지 제공
2) 설치 & 가입 앱 스토어 다운로드, 계정 생성 “설정 과정이 번거로우면 어떡하지?” 복잡한 인증, 많은 입력 항목 간단한 온보딩, 용어 설명 툴팁 제공
3) 자산 연동 외부 금융사 연동 동의 및 계좌 연결 보안·개인정보 제공에 대한 걱정 신뢰 부족, 연동 실패 경험 인증 단계별 설명 & 시각화, 재시도 플로우 제공
4) 탐색 대시보드, 추천 영상/라이브 탐색 “내 상황에 맞는 정보를 찾고 싶다” 정보 과다, 어디서 시작해야 할지 모름 맞춤 피드, 가이드 태스크 플로 제공
5) 참여 라이브 시청, 채팅, 질문, 커뮤니티 참여 함께 보는 느낌, 소속감 단순 일방향 방송, 질문 미응답 Q&A 고정, 답변 하이라이트, 커뮤니티 연계
6) 유지 반복 방문, 알림 기반 재유입 “이 앱은 계속 써볼 만하다” 피드백 반영 속도 느림 피드백 로그 공개, 개선 히스토리 노출

9. 구현 계획 (MVP 기준)

9-1. 단계별 로드맵

  1. MVP 1: 자산 통합 대시보드 + 기본 온보딩/로그인
  2. MVP 2: 맞춤 영상/라이브 추천, 전문가 팔로우 피드
  3. MVP 3: 라이브 채팅 & Q&A, 커뮤니티 채널
  4. MVP 4: 고급 리포트 & 리스크 분석, 피드백 로그 공개

9-2. 협업 관점

  • 기획: 요구사항 정의서·화면 설계서 유지 및 변경 이력 관리.
  • 디자인: 와이어프레임 기반 UI 키트 설계 (모바일 우선).
  • 개발: 외부 금융사 API 스펙 협의, 보안/인증 정책 정의.
  • 운영: 라이브 편성, 전문가 섭외 및 커뮤니티 운영 정책 수립.
